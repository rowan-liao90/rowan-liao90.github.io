## 先讲一个故事

去年聊了10家企业，8家问："你们有什么大模型？"

我问他们："你们的问题是什么？"

答曰："不知道，但大模型很火，先上一个。"

这8家里，6家后来项目失败了——不是因为大模型不好，是因为大模型根本不是他们的问题。

**技术选型的第一课：先问问题，再选工具。**

## 技术选型四象限

我画了一个技术选型四象限，帮助企业老哥/老板们做判断：

```
                    问题复杂度
        低 ◀──────────────────▶ 高
        │
 高     │   ┌─────────────┬─────────────┐
 业     │   │   知识库     │   AI Agent  │
 务     │   │  (文档问答)  │  (复杂任务) │
 替     │   ├─────────────┼─────────────┤
 代     │   │    RPA      │   大模型    │
 度     │   │ (流程自动化) │ (智能决策)  │
        │   └─────────────┴─────────────┘
 低     │
        └──────────────────────────────────▶ 高
                  技术复杂度
```

### 象限一：知识库（低问题复杂度 + 低技术复杂度）

**适用场景**：
- 文档问答（FAQ、产品手册、制度文件）
- 客服机器人（标准问题回答）
- 内部知识管理

**典型案例**：
- 合同审查：上传合同，AI提取关键条款
- 政策查询：员工查询公司制度
- 产品知识库：客服快速查询产品信息

**技术要点**：
- RAG（检索增强生成）是核心
- 向量数据库：Pinecone、Milvus、Chroma
- 文档解析：PDF、Word、PPT

**投入产出**：
| 项目 | 数值 |
|------|------|
| 开发周期 | 2-4周 |
| 投入成本 | 10-30万 |
| 适用规模 | 中小企业 |

### 象限二：RPA（低问题复杂度 + 高技术复杂度）

**适用场景**：
- 数据录入（Excel→系统）
- 报表生成（定时任务）
- 跨系统操作（多系统协同）

**典型案例**：
- 财务对账：自动从银行下载流水，匹配ERP数据
- 人事录入：新员工入职，自动同步信息到多个系统
- 订单处理：自动从电商平台抓取订单，同步到ERP

**技术要点**：
- UIpath、实在智能、来也科技等平台
- 适合规则明确、流程固定的任务
- 不是"AI"，是"自动化"

**投入产出**：
| 项目 | 数值 |
|------|------|
| 开发周期 | 1-4周/流程 |
| 投入成本 | 5-20万/年 |
| ROI | 通常6-12个月回本 |

### 象限三：AI Agent（高问题复杂度 + 低业务替代度）

**适用场景**：
- 多步骤任务执行（需要调用多个工具）
- 对话式任务（私人助理、客服升级）
- 复杂流程编排（跨部门协同）

**典型案例**：
- 会议助手：自动安排会议、发送邀请、记录纪要
- 销售助手：自动生成报价单、跟进客户、维护CRM
- 供应链助手：自动监控库存、预测需求、生成采购单

**技术要点**：
- 规划能力：把复杂任务拆解成步骤
- 记忆能力：记住上下文和历史
- 工具调用：调用API、读写文件、操作软件
- 多Agent协作：多个Agent协同完成复杂任务

**投入产出**：
| 项目 | 数值 |
|------|------|
| 开发周期 | 1-3个月 |
| 投入成本 | 50-200万 |
| 适用规模 | 中大型企业 |

### 象限四：大模型（高问题复杂度 + 高业务替代度）

**适用场景**：
- 智能决策（风险评估、投资分析）
- 内容生成（营销文案、设计创意）
- 复杂推理（法律分析、医学诊断）

**典型案例**：
- 智能风控：实时评估贷款风险
- 智能写作：批量生成营销内容
- 智能诊断：辅助医生看片子、写报告

**技术要点**：
- 模型选型：GPT-4、Claude、国产大模型（文心、通义、混元）
- 部署方式：云端API、私有化部署、微调
- 能力边界：懂什么、不懂什么

**投入产出**：
| 项目 | 数值 |
|------|------|
| 开发周期 | 3-6个月 |
| 投入成本 | 100-500万 |
| 适用规模 | 大型企业 |

## 技术选型决策树

遇到具体问题，按这个决策树来：

```
问题是什么？
│
├─ 有明确答案 → 是/否判断？
│   │
│   ├─ 规则明确 → RPA（自动化规则）
│   │
│   └─ 需要理解 → 知识库（RAG问答）
│
├─ 多步骤任务？
│   │
│   ├─ 流程固定 → RPA（流程自动化）
│   │
│   └─ 流程灵活 → AI Agent（任务编排）
│
└─ 需要智能决策？
    │
    ├─ 有足够数据 → 大模型（智能推理）
    │
    └─ 数据不足 → 先做数据基础
```

## 技术选型避坑指南

### 坑1：技术驱动而非业务驱动

**表现**：上来就问"你们有什么大模型"，不管业务问题是什么

**后果**：技术很好，但解决不了问题

**避坑**：先明确业务问题，再匹配技术方案

### 坑2：追求大而全

**表现**：一次性上所有技术，系统超级复杂

**后果**：项目周期太长、预算超支、团队疲惫

**避坑**：小步快跑，先做速赢场景

### 坑3：忽视数据基础

**表现**：数据一团糟，上了AI效果很差

**后果**：AI是"垃圾进、垃圾出"

**避坑**：先做数据治理，再上AI

### 坑4：忽视组织变革

**表现**：技术上去了，业务部门不会用、不想用

**后果**：系统上线了，没人用

**避坑**：技术选型时考虑组织接受度，提前做变革管理

## 核心判断

> **技术选型的金线，是"合适"而不是"先进"。** 不是比谁用的技术最新，是比谁能用对的技术解决对的问题。
>
> 记住九个字：**不着急，不害怕，不要脸。**
> - **不着急**：别被"大模型焦虑"带偏，先搞清楚问题
> - **不害怕**：RPA、知识库不是"low"，能解决问题就行
> - **不要脸**：不懂技术就问，问清楚了再选

## FAQ

**Q: 什么情况必须上私有化部署？**
A: 数据敏感度高（如金融、医疗、政府）、合规要求严格、有定制化需求时。

**Q: 国产大模型够用吗？**
A: 够用。国产大模型（文心、通义、混元）在中文场景表现已经不输GPT-4，而且成本更低、合规更好。

**Q: AI Agent和RPA有什么区别？**
A: RPA是"死板"的自动化，规则定了就按规则走；AI Agent是"聪明"的自动化，能理解意图、灵活应变。简单任务用RPA，复杂任务用Agent。

**Q: 知识库和大模型有什么关系？**
A: 知识库是大模型的"外挂硬盘"。大模型本身不知道你的企业知识，但通过RAG技术，可以从知识库里检索相关信息给大模型用。
